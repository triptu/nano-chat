Nano Chat

An Android chat app that talks to on-device models, with a list of companions like WhatsApp contacts. Each companion now runs on either Gemini Nano or Gemma 4 E4B, and Gemma also takes photos and voice notes. Everything is committed on main, and a release build is installed on the Galaxy Z Fold 7 with Gemma downloaded. Start with the comparison just below. You don't need to do anything unless you want to answer the open questions at the bottom.

My read on quality

Gemma 4 E4B is clearly better for chat. It follows the personality: it asks what's in the fridge in every reply, it keeps its lists to real steps, and it adapts when told there is no oven-safe pan. Nano ignores the "only use a list for steps" rule every time, pads with lines like "Enjoy your dinner!", and gives no method for setting the eggs on the stove. Neither made a factual cooking mistake in this run, but Nano's run on this page last week suggested a roux for a frittata. On photos the two are closer than I expected. Each names about four items correctly and invents one. Gemma turns it into a better conversation, while Nano lists vegetables. Voice notes only work on Gemma, and the one I tried was understood perfectly. Gemma's cost is memory: it takes 4 to 5 GB of the phone's 12 GB, and Android killed the app twice during my tests (see Known issues).

Under the hood

  • Kotlin, Compose BOM 2026.09.00, Material 3 1.4.0, M3 adaptive 1.3.0, AGP 9.4.1, Kotlin 2.4.21, Gradle 9.8.2, Room 3.0.3, DataStore 1.3.0, genai-prompt 1.0.0-beta4. Each version is the latest stable on Maven as of today.
  • The model sits behind one interface with two backends. One is ML Kit. The other is a fake that streams canned replies at realistic speed and can pretend to need a download, be busy, run out of quota or be unsupported.
  • Six behavioural tests run on the fake: the prompt fits the token budget, the system prompt goes inline when needed, an oversized message is rejected, streaming and the output cap work, a quota error is raised, and a made-up next turn is trimmed. All pass.
  • An upgrade over an existing install keeps chats: the database moved from version 1 to 2 on the phone without losing data.

Decisions

Home is a list of companions, created with "New friend"

Chose a WhatsApp-style list, where each companion is one ongoing thread. The button and sheet say "New friend". Flip it if you want another word (for example "New companion").

Three starter companions

Chose Nano (coral, general helper), Basil (sage, cooking buddy) and Sunny (apricot, pep talks). Edit, clear chat and delete are in the chat's overflow menu. Clear and delete ask for confirmation because they can't be undone.

Warm look

Chose a cream background, coral user bubbles with dark text, white agent bubbles, and a warm brown dark theme. The type is Nunito (bundled, OFL) and the icons are Phosphor, converted to vector drawables. The blob mascot is the adaptive app icon and every avatar, tinted with the companion's colour. From Meta's Muse I took two ideas: a status line under the avatar ("thinking…", "typing…", "on your phone"), and the mascot standing in for a spinner. I left out split bubbles and emoji reactions.

Developer tools on by default, behind one switch

Chose one DataStore boolean, read once at the root and passed down. Every dev surface lives in the devtools/ folder. Switching it off also forces the model choice back to Auto.

Real or fake model

Chose Auto, Real and Fake options on the nerds page. In a release build, Auto always means the real model. In a debug build, Auto uses the fake only when the real model reports unavailable, as on an emulator. The nerds page and the chat internals sheet both show which model is running.

How the prompt is built

The Prompt API has no multi-turn support, so each request is a transcript with ## section headers. It starts from the newest message and adds older turns while they fit, within 4000 tokens or the model limit minus the output cap, whichever is smaller. The personality goes in as a system instruction when the model supports one. Otherwise it starts the prompt as a cached prefix, which is the case on the Fold's nano-v2. I added a short length guide to every personality ("2 to 5 friendly, specific sentences").

Replies keep running when you leave a chat

Chose an app-wide engine that runs one reply at a time, so the home row shows "typing…". If you press stop, the partial reply is kept. If the model fails partway, the partial reply is dropped, as the ML Kit docs recommend, and a friendly message with "Try again" appears.

Default model settings

Chose temperature 0.7, top K 40 and 512 max output tokens. You can change them on the nerds page, and each companion can override them in its edit sheet when dev tools are on.

Room 3 instead of Room 2

Chose Room 3.0.3, the newest stable version, with the bundled SQLite driver.

Two panes from 600 dp wide

Chose a 380 dp list pane, with the chat, profile and nerds page opening in the right pane. Opening another chat replaces the current one instead of stacking it, so back goes straight to the list.

Emulator for UI work, the Fold only at the end

All UI iteration ran on a Pixel 9 Pro Fold emulator I created, folded and unfolded. I left the shared phone emulator alone after another app came up on it. Debug builds include a broadcast receiver that sends a message without the keyboard, for scripted screenshots. It isn't in release builds.

Package and release signing

The package is ai.tushar.nanochat with minSdk 31. The release build is minified and signed with the debug key. ML Kit needed R8 keep rules, because its beta crashes on launch without them.

Scope: only Gemma 4 E4B, plus multimodal input

You narrowed the brief mid-run: Gemma 4 E2B and Qwen3 4B are out, and photo and voice note input is in. Neither dropped model had been downloaded, so there was nothing to delete.

Gemma runs through LiteRT-LM 0.18.1, the latest stable

com.google.ai.edge.litertlm:litertlm-android:0.18.1 from Google Maven, released 2026-10-20. The engine loads on the GPU and falls back to the CPU if the GPU fails. Photos go through the GPU vision encoder and voice notes through the CPU audio encoder, as in Google's AI Edge Gallery app. I tried the vision encoder on the CPU too. It used the same memory and wasn't faster. I didn't try the NPU: there is no Gemma 4 E4B build for the Fold's Snapdragon 8 Elite (SM8750) on Hugging Face.

The 3.66 GB model file, downloaded in the app

The Hugging Face repo litert-community/gemma-4-E4B-it-litert-lm is not gated, so the app downloads gemma-4-E4B-it.litertlm directly. No login or token is needed. This is the same file the Gallery app uses, and it includes the vision and audio encoders and multi-token prediction. A download can be cancelled and resumes where it stopped. The file goes in the app's external files folder, so adb push to the same path also works.

Gemma gets a real system instruction and native multi-turn chat

Nano needed the personality pasted into the prompt. Gemma takes it as a system instruction, and the earlier turns go in as real chat messages. Each chat keeps its live conversation, so on the next message the model already has the earlier turns in memory and only reads the new one. If the history changes (cleared, a turn dropped for space, another chat), the conversation is rebuilt from the saved messages. Gemma's thinking mode is off, so replies start right away.

Context size is set per model: Gemma gets 2,048 tokens

Nano keeps its 4,000-token input cap. Gemma's window is 2,048 tokens, input and output together, so about 1,500 tokens of chat history after the 512-token output cap. The model supports 32k, but each token of window costs about 180 KB of GPU memory. On the Fold, 8,192 got the app killed on the first reply, and 4,096 was killed once with other apps open. 2,048 ran every test cleanly. It's one number in litert/LiteRtModels.kt. See open question 1.

Speculative decoding is on when the file supports it

The app asks the model file whether it supports speculative decoding (Gemma 4's multi-token prediction) and turns it on if so. The dev tools show whether it's on.

How many photos stay in the context

Each photo goes to the model as a 768 px PNG at Gemma 4's 280-token setting, and the full-size copy stays for display. The newest message's photos and voice notes always go in. Older ones go in, newest first, until media would use more than 40% of the input budget, and at most 4 photos per request. Anything left out becomes a "[photo]" or "[voice note, 8 s]" marker, so the model knows it was there. With the 2,048-token window that's two photos at most, so in practice the newest photo plus one older one. Nano's Prompt API takes one image per request, so Nano sees only the newest photo and no audio. The internals sheet shows how many photos were sent and how many were left out.

Voice notes: tap to record

Tap the mic to start recording, then cancel, stop (keeps the note as a draft so you can add text) or send. Hold-to-record was the other option. Tap felt more reliable on a large screen, and it lets you add words before sending. Notes are 16 kHz mono WAV, up to 30 seconds, which is the format the Gallery app sends to Gemma. The microphone and camera permissions are asked for the first time you tap that option. If you deny one, a short line explains why and links to Settings.

Nano gets photos too, but not voice notes

ML Kit's Prompt API takes one image per request, and it worked on the Fold. So Nano companions get the attach button with Photo and Camera, and no Voice note. One fix was needed: ML Kit rejects a cached prompt prefix on requests with an image, so those requests skip the cache.

How photos are stored

Photos and voice notes are saved in the app's private storage, never in shared storage, and listed in a new database table, so existing chats survived the upgrade. Each photo is saved twice: a full-size copy for the chat and a 768 px PNG for the model. Clearing a chat or deleting a companion also deletes its files. Tap a photo to view it full screen.

The download screen moved into the chat

The whole app used to wait behind Nano's gate. Now the list always shows, and a chat whose model isn't ready shows the mascot download screen in its place, with size, progress and cancel. It also has a link to switch that companion to the other model.

Global default stays Gemini Nano

New companions use Nano unless you pick Gemma, so nobody has to download 3.66 GB before their first chat. You can change the default on the nerds page.

Open questions

1. Gemma's context: 2,048 tokens or 4,096

At 2,048, Gemma remembers about the last 6 to 8 short messages and at most two photos. At 4,096 it would remember twice as much and use about 0.4 GB more, and the app was killed once at that size with other apps open. My pick is to stay at 2,048 until Android can kill the app without losing the reply: unload Gemma when the app goes to the background, and show "Try again" after a restart. Then try 4,096.

2. Should Gemma be the default for new companions?

It replies better and faster once loaded. The costs are a 3.66 GB download, about 10 s of loading each time the app starts, and 4 to 5 GB of RAM. My pick is to keep Nano as the default and suggest Gemma in the editor. Flip it on the nerds page if you want everything on Gemma.

3. How hard to push reply quality on nano-v2

The Fold 7 runs nano-v2. Its replies are short, sometimes wrong (it suggested a roux for a frittata), and it drifts back to old topics: when told "that's all I needed", Basil replied with a full recipe. Options:

  • (a) Lower the default temperature to about 0.4.
  • (b) Add one example exchange to each starter personality.
  • (c) Send fewer old turns.

My pick is (a) and (b) together, then compare on the phone. Nothing is blocked meanwhile.

Known issues

Android can kill the app while Gemma is loaded

Gemma takes 4 to 5 GB, which leaves about 1 GB free on the Fold. Twice during testing, with a larger window and other apps open, Android's low-memory killer stopped Nano Chat in the middle of a reply. When that happens, your message stays in the chat without a reply, and you have to send it again (there's no "Try again" on the next start). The app then reloads the model, which takes about 10 seconds, and rebuilds the chat (4.6 s to the first token in the release test, because two old photos were read again).

Downloads run only while the app is open

The 3.66 GB download runs inside the app, not as a background job. If Android closes the app, the download stops. It resumes from where it stopped the next time you tap Download.

Not measured

The token cost of voice notes is estimated at 25 tokens per second; I didn't measure it. TalkBack, large fonts, the unfolded inner screen with Gemma, and a voice note recorded on the real mic were not checked. The test note was made with macOS text to speech and sent through the debug receiver, and recording was checked only on the emulator.

Nano reply quality

See open question 3. One reply also started with a stray "1.".

Not checked on the real phone

The cover screen (the phone stayed unfolded) and light mode (the phone was in dark mode).

Not checked anywhere

A full TalkBack walk, 200% font size, and a 320 dp width. The review fixes for these are in: speaker labels on bubbles, live regions, labelled switches and sliders, and wrapping colour swatches.

Prefix caching showed no speed gain

The first token took 1.2 to 1.5 s with or without the cached prefix, but the prompts were short (100 to 280 tokens). It may matter in long chats.

Small UI rough edges

A back press during a pane transition can be ignored. Opening a chat shows one frame with an empty title while the companion loads.

English only

UI text is written in code, not in strings.xml, so it can't be translated yet.
